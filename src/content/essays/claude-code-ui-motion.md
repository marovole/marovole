11 月 7 日，设计工程师 Breeje Anadkat（简介写着白天做设计工程师、晚上在 [cosmaha.com](https://cosmaha.com) 卖模板）发了一串帖子，展示他怎么用 Claude Code 做出一组 iOS 应用界面和动效（[原帖](https://x.com/BreejeAnadkat/status/2119040284088787421)）。原帖浏览量到了 **215.1K**，拿到 **3.4K** 个赞。

从他晒出的视频封面截图里能看到（【图片转录】），屏幕上并排放着两台运行 iOS 26.5 的 iPhone 17 Pro 模拟器，右边那台界面顶上是蓝天白云，底下接着一张写着「Hi, James / Welcome Back」和「0 Days」的打卡卡片，底部排着 Home、Path、Shop、Progress 四个标签。

评论区里，读者 Razpe Carlson（`@c_razpe`）留了一句很准的评价：真正卖座的是动效，静态界面看起来和其它 AI 做的应用没什么两样，而动画会让人觉得背后有一个完整的团队（[评论原文](https://x.com/BreejeAnadkat/status/2119040284088787421)）。

很多人以为要做出这种效果，得先去啃 Swift 或者学动画曲线。其实不用。我平时在非技术公司做一线 FDE，每天带不写代码的同事用 AI 做工具，最深的感触就一句话：不用学写代码，学会像产品经理一样指挥 AI。

把 Breeje 这串帖子和三张配图拆开看，你会发现他真正用功的地方根本不在提示词修辞，而在三件事：给参考、拆状态、对色号与交互手感。

## 一、打破一把出奇迹的幻想，把形容词换成参考图

Breeje 在第一条帖子里直接泼了冷水：这些界面大多经过了好几轮提示，如果你指望一次生成（one shot）就拿到这种结果，你大概率停在了粗糙的初稿上。他的起步动作是告诉 Claude 这个应用干什么，同时发过去几张 UI 和动效参考图（[Thread 1](https://x.com/BreejeAnadkat/status/2119040510610546726)）。

最有意思的是他配的第一张聊天截图（【图片转录】）。他在输入框里敲的那段英文非常口语，连标点都没打全（中间还有一小段打了白码）：他说想用 Swift 做一个随机应用（`i want to make a random app in swift`），让 Claude 看附带的视频，说自己喜欢里面滑动切换不同类型的方式，想用这种方式来搜电影，想要独特丝滑的动画和性感的 UI，深色主题配液态玻璃质感（`dark theme with liquid glass`）。

为什么文字写得这么糙，出来的东西却不糙？

看那张截图的上半部分就明白了（【图片转录】）。他在输入框上方一口气挂了 4 张具体的视觉参考图，外加 1 段手机视频缩略图。那 4 张参考图里，有带「Sunrise to sunset / Scheduled」与「NOW / 6AM / 12PM / 6PM」时间轴刻度的暖橙色卡片，有散落照片卡片的拍立得风格界面，还有深色背景下的圆弧列表。

我带同事用 AI 时最常看到的卡点，就是大家在对话框里憋半天形容词。形容词对模型来说全是噪音。Breeje 的文字虽然随意，但那 4 张参考图和 1 段视频，已经把元素密度、圆角比例、冷暖对比和滑动方式锁死了。

## 二、并排看图找茬，把「不好看」拆成色号和圆角

拿到初稿之后怎么改？Breeje 在第二条帖子里说，他的 UI 参考主要从 Mobbin 和 Pinterest 上找。有些页面如果先在 Figma 里画出来，反而更快到位；然后他会把 Figma 设计稿和 Claude 做出来的界面并排放一起，直接指出具体哪里要改（[Thread 2](https://x.com/BreejeAnadkat/status/2119041908312003042)）。

他晒出的第二张聊天截图（【图片转录】），就是一张很标准的视觉验收单。上面挂着 4 张从 Figma 截出来的界面图：前两张是同一个带「R」字图标的求职应用（分别框选了主标题 `Swipe right on your next job.` 和下方副标题），下面排着 `1.2M Applications Sent`、`4.7 App Store Rating`、`4.2M Job Seekers` 三组数字；第 3 张是一个分别标着 `53 Good` 和 `83 Best` 的半圆仪表盘，第 4 张是写着 `Software Engineer $250k-300k San Francisco, CA` 的职位卡片。

看他在输入框里怎么下指令（【图片转录】）：

- 先修图 1 和图 2 里的文字问题（`fix text thing in image 1 and 2`）；
- 到了图 3 的仪表盘，要修颜色和结构，他直接给出两个十六进制色号：`E0A150 - good color`，`38CD76 - best color`；
- 再看图 4，去修圆角半径等细节（`see image 4 lets fix corner radius etc for here too`）。

这就是「许愿」和「验收」的区别。跟 AI 说「颜色不好看，调得高级一点」，模型只会瞎猜；把 Figma 设计稿和生成结果放在一起比对，截出设计稿里的目标样式，直接告诉它 Good 用 `E0A150`、Best 用 `38CD76`，它一次就能改对。不会写代码，完全不耽误你截一张图、吸一个色号。

## 三、找不到参考的 5%–10% 复杂动效，拆成 3 个状态

第三条帖子是整串内容里最值钱的一招。Breeje 说，他平时一般直接发一段动效参考给 Claude；但大约有 **5–10%** 的时候，找不到合适的视频片段，或者动画本身太复杂，他就会在 Figma 里画出 **2–3** 个状态，发给 Claude 并解释清楚每个状态以及它是怎么运作的（[Thread 3](https://x.com/BreejeAnadkat/status/2119042314849202236)）。

他晒出的第三张图（【图片转录】），在黑色画布上从上到下排着同一个滑动按钮的 **3** 个状态：

- `1st state`：深色胶囊轨道，左边停着暗灰色的短胶囊形箭头按钮，中间写着 `Swipe to add entry`；
- `2nd state`：左边按钮变成高亮白色，右侧边缘亮起一圈绿色的发光光晕；
- `3rd state`：白色按钮往右推到了胶囊中间，滑过的左半边轨道留下一道绿色的渐变光带，原本的文字被盖住一半，只露出 `Swipe to`。

很多人一听写动效就发怵，觉得不懂代码怎么跟 AI 讲清楚动画。其实从产品和程序逻辑来看，连续动画拆到底就是「状态 1 变到状态 2，再变到状态 3」。你不去管中间的过渡函数怎么写，只要把头、中、尾三个关键状态画出来，说明白什么条件下触发、哪个元素变亮、哪个元素位移，AI 最擅长补齐中间那段过渡代码。

## 四、视频里好看 ≠ 点起来顺手，以及最后那 2 像素

代码跑起来还不算完。Breeje 在第四条帖子里说，接下来他会去测试这个应用：一段过渡动画在视频片段里看着很棒，亲手点过去却可能依然觉得慢。而且他自嘲说，到了最后，他的设计师本能通常还是会逼着自己把一个标题往上挪 **2px**（[Thread 4](https://x.com/BreejeAnadkat/status/2119042592411377801)）。

那条帖子下面，另一位开发者 `@ahurein_e` 补充了一个很实的配合方式：把活拆开，让 Claude 负责写实现，再让带 computer use 的 Codex 去实际点击 UI，因为一段好看的演示视频依然可能藏着别扭的流程（[评论原文](https://x.com/BreejeAnadkat/status/2119042592411377801)）。

顺带一提，Breeje 在第五条帖子里写着如果创始人找既懂设计又能把 MVP 做上线的人可以私信他（[Thread 5](https://x.com/BreejeAnadkat/status/2119042717217112234)），并在原帖评论区放了自己的 Cal.com 预约链接（[原帖](https://x.com/BreejeAnadkat/status/2119040284088787421)）。我去翻了他的模板站 [cosmaha.com](https://cosmaha.com)，上面卖的 Framer 模板定价在 **$79**、**$99** 到 **$129** 不等（也有免费模板），页面上写着已经有 **125** 位创始人用他们的模板上线了网站。把自己的真实工作流拆开晒出来，本身就是最管用的作品集。

## 五、普通人今天就能照抄的三个动作

如果你不会写代码，但也想用 Claude Code 做出拿得出手的界面，Breeje 这套做法正好对应产品经理指挥 AI 的三步：

**第一步，说清需求：戒掉形容词，先找参考图。** 别在输入框里堆砌「极简」「高级」。去 Mobbin 或 Pinterest 截几张你想要的界面，哪怕配上一句粗糙的大白话，也比写三百字修辞管用。

**第二步，拆成步骤：复杂动效画成 3 个静止状态。** 遇到找不到现成参考的交互，别用文字绕口令去描述动画。拿画图工具或 Figma 摆出「初始、触发、推到一半」3 个状态，标清每个状态变了什么。

**第三步，验收结果：并排贴图报色号，最后亲手点一遍。** 把 AI 做的图和参考图并排放在一起指出差异，颜色直接报 `E0A150` 这样的具体色号；做完一定自己点一遍流程，看看有没有「录屏很好看、点起来嫌慢」的过渡。

## 六、我还没想清楚的地方

看完这串帖子，我一直在想一个问题。

当 Claude Code 把「实现一个带绿色光晕的滑动按钮」压缩到几轮对话，写代码本身早就不再是门槛了。但最后决定这个东西看起来像「随手生成的半成品」还是「像一个完整团队做出来的产品」的，恰恰是那 **5–10%** 找不到现成参考、必须你自己动手拆出 **3** 个状态的时刻，以及亲手点完觉得慢、非要把标题往上挪 **2px** 的那点较真。

工具可以把实现的成本压到极低，但「点起来觉得慢」的体感，还有盯着屏幕看出标题偏低 **2px** 的眼睛，目前还没法靠一行提示词自动生成。不用学写代码，学会像产品经理一样指挥 AI，这句话真正难的从来不是「指挥」那一下，而是指挥完之后，你知不知道什么叫好。
