## 我想解决的问题

Web3 的研究环境，是刻意为难你的。

数据是存在的——区块链交易是公开的，代币分配在链上，团队历史可以追溯——但从噪音中提取信号，是一件折磨人的事。对一个新协议做一次认真的研究，要花好几个小时：抓取文档、阅读白皮书、交叉验证代币经济学、检查巨鲸钱包行为、核实解锁时间表、评判团队可信度。

大多数人不会这样做。他们读 Twitter 线程，根据社交动量做决策。骗局操盘手深知这一点，并系统性地加以利用。

现有工具帮不了多少忙。价格追踪器给你滞后指标。链上浏览器给你没有解读的原始数据。AI 助手用令人不安的自信编造代币事实。"我想了解这个项目"和"我有足够信号做判断"之间的鸿沟，依然很大。

Web3search 是我压缩这道鸿沟的尝试——把严谨的研究从数小时压缩到数分钟，并把红旗自动浮出水面，而不是寄望于用户知道该找什么。

## 我做了什么，为什么这样做

**角色：** 独立设计师兼开发者——产品概念、UX 架构、AI 集成、后端基础设施和部署，均由我负责。

产品有三个核心组件，分别解决研究问题的不同维度：

**深度研究** 回答"这个项目是什么"——运行多源查询，综合文档，生成带引用的结构化简报。

**ScamMeter（骗局指数）** 回答"我该不该信任这个项目"——从多个风险维度对项目评分：团队匿名性、代币集中度、解锁悬崖时机、合约验证状态、社交背书质量。

**代币分配分析** 回答"谁真正持有这些代币"——巨鲸集中度、交易所与散户余额、解锁时间表压力。

### Glass Box UX 的设计决策

Web3search 最刻意的设计选择，是我称之为 Glass Box UX（玻璃盒用户体验）的东西：AI 在研究过程中实时展示其思维链。

在大多数 AI 产品里，答案在加载转圈之后出现。你得到结论，但看不到推理过程。在信任稀缺、错误昂贵的领域，这是错误的权衡。

展示思维链有几个作用：

1. 用户可以实时发现错误——如果 AI 错误识别了一个代币代码，他们看到了，知道要修正查询
2. 研究过程本身有教育价值——用户通过观察 AI 追踪哪些问题，来学习什么问题是重要的
3. 透明是可信度信号——在 Web3 里，不透明本身就是红旗，所以产品对自己过程的透明，强化了正确的直觉

实现上使用流式响应与结构化状态——每个推理步骤在完成时发射，UI 带来源标注地渐进式渲染。

### 多模型 AI 路由

我通过 OpenRouter 跨三个不同的 AI 后端路由：DeepSeek、GPT 和通义千问。路由逻辑不是随机的——不同类型的查询根据成本-质量权衡分配给不同模型。

事实查询和数据提取走更便宜、更快的模型。对项目经济设计或团队可信度信号的复杂推理，走能力更强的模型。用户看不到这层路由——他们只看到稳定的质量和合理的成本。

这是一个刻意的架构选择，对抗"所有事情用同一个模型"的做法。单模型方案要么在简单查询上过度消费，要么在复杂查询上投入不足。多模型路由让系统按查询优化，而不是按会话优化。

### 搜索层：多源而非单源

我组合使用 Brave Search、Tavily 和 Serper，而不是单一搜索提供商。每家的索引特性不同：

- Brave 倾向更新内容，Web3 结果中 SEO 垃圾更少
- Tavily 更擅长找到技术文档和 GitHub 内容
- Serper 在新闻和社交提及的覆盖面更广

编排层并发查询多个来源，去重后再传给推理模型。比任何单一来源都能产出更丰富的研究结果。

### 基础设施：为什么选择 Cloudflare Workers + Hono

Web3search 的延迟要求，与传统服务器部署不兼容。实时价格数据意味着亚秒级 API 调用。流式思维链意味着长连接。用户分布在全球各地。

Cloudflare Workers 在 300+ 个节点运行于边缘，消除地理延迟。Hono 是一个轻量级路由器，原生支持 TypeScript，在 Workers 上原生运行——这个组合在没有冷启动惩罚的情况下处理高并发流式响应。

Supabase 管理对话历史和用户会话。多轮上下文保留（记住三个问题之前问了什么）对探索式研究工作流很重要——用户是在层层深入，而不是单次查询。

## 最难的部分

**阻止自信的幻觉。** 训练过 Web3 内容的 AI 模型，往往携带来自训练数据的过时或错误代币信息。原始做法——直接问模型某个代币——产出听起来合理但实际错误的答案。

解决方案是强制检索：模型不能仅凭训练数据回答。每个事实声明必须基于实时检索到的内容。模型的职责是解读和综合，不是记忆。这需要精心的提示工程和输出验证，来捕捉模型退回训练数据模式的情况。

**ScamMeter 的校准。** 一个骗局评分是一个很强的声明。弄清楚哪些维度真正能预测 rug pull，而不是只是项目有激进的代币经济学——这需要研究真实案例。当前模型明确说明它在衡量什么和不衡量什么，输出的是分项而不是单一数字，正是因为单一数字会暗示比系统实际具备的更高精度。

**可变延迟下的流式 UX。** 研究流水线有多个异步阶段，完成时间不同。把流式 UX 做对，让部分结果有用而不是令人困惑，需要细致的状态管理。用户不应该盯着半渲染的分析，不知道系统是卡住了还是还在工作。

## 成果与现状

Web3search 在 [lulaai.xyz](https://lulaai.xyz) 作为工作研究工具上线。核心研究闭环——查询输入、多源研究、Glass Box 推理、结构化输出——已端到端可用。

可以具体说明的是：

- 多模型路由在保持复杂分析质量的同时降低了每次查询成本
- Glass Box UX 提升了用户与研究过程的互动——体感上，用户花在阅读推理链上的时间多于阅读摘要
- ScamMeter 框架浮出了单指标工具会错过的结构化风险信号

这是一个有真实效用的工作原型，不是打磨好的消费级产品。AI 路由和搜索层架构是可扩展的；UX 和覆盖面的迭代需要基于真实用户反馈。

## 我学到了什么

核心洞察：**在低信任环境里，得出答案的过程和答案本身一样重要。**

Web3 是一个人们被自信的错误信息烧过的领域——来自 KOL、来自项目方、来自彼此。一个展示工作过程的工具，不只是在做透明度；它在提供一种与 AI 输出不同的关系。用户变成了研究的协作者，而不是结论的消费者。

第二个教训：**多模型路由被严重低估。** 全部走强模型与按查询复杂度路由之间的成本差异，在有量的情况下非常显著。构建这个路由层前期工程量更大，但对任何需要经济可持续的 AI 产品来说，这是正确的长期架构。

如果重来一次，我会更早优先处理 ScamMeter 的校准。弄对那个评分模型，是产品中最难也最有价值的部分——同时也是答错了后果最严重的部分。
